- 一打開終端機，就會進入你的根目錄
    - C:\Users\User\Desktop\1234>
    - 如果你創建專案的語法是  uv init -app myapp 專案名稱是myapp
    - 我希望是直接在這個資料夾裡創建專案
    - uv init --app . 點的意思就是這個資料夾裡面
- git 是一個版本管理工具
    - 我們的程式碼常常需要更改 所以就會有板次
    - 那我們也會有程式碼正常運作 但是要繼續開發新功能 需要紛版次 方辦如果改錯 還恢復上一版
- git 是本地版本的控管工具
    - 如果需要跟其他人共同處理專案 菜惠需要github
        - 自己一個人也可以把github當儲存庫
    - 如果從本地 ==> github完整的程式碼會有三個階段
        - 變更            在git控管的專案裡面 只要檔案改了 就會進入到變更專區 檔案狀態是U
        - 暫存(stage)     就從變更專區加入 這個時候會把一些打算寫進同一個改良版的東西都放進來 檔案狀態A
        - 確認同意(commit) 一次性的把所有的變更打包確認為一個新的板次
            - 要提交 需要留下訊息 方便下次找回
            - 要提交的時候需要留下簽名 知道誰做了這個提交 所以會需要在終端機設定NAME和EMAIL 
            - git config --global user.name "yu"
            - git config --global user.email "ftp20345918@gmaul.com"
            - 提交後檔案會消失
        - 推送(push)      把本地端的改變和雲端的內容合併(這裡面就開始有其他人的改變在裡面)
- 有些檔案和資料夾 我們是無會上傳到git的
 - 可能是很大的資料 比如.venv 這個靠uv.lock可以復原 不用上傳
 - 或是帳號密碼檔案 這個我們也不會上傳
 - 所以會用 .gitignore 來設定 ignore就是忽略
- git 是一個很善變應用的工具 所以uv建立專案的時候 就會幫你做了git設定
    - 你看到變更裡面 u代號的是完全沒有出裡的檔案

- push就從 local到hub
- 我也會反向推 提取(pull)就是把雲端版本拉下來
    - 在提交push的過程
    - 有可能改的部分跟他人衝突 git會跳出提示 讓你選擇
        - 接受變更
            - 就是你local端的改法
        - 接受來源變更
            - 就是hub端的改法
